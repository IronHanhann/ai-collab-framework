# 样例四：那六个状态文件长什么样

> 虚构样例。**只有结构和字段说明，没有任何真实数据。**
> 这六个文件在你的**项目目录**里（`projects\<项目名>\`），不随 skill 包分发——
> 你部署框架后它们会在你自己的目录里长出来。
> （框架根除了一个 SWITCH.md 总开关，只剩协议规定的 CONTROLLER.md / FRAMEWORK.md / USER-GUIDE.md）

---

## SWITCH.md —— 开关

项目级开关。新项目**默认 `enabled: false`**，人到齐才翻 `true`。

```markdown
# 项目开关（{项目名}）

## 当前状态

​```yaml
enabled: false
mode: normal
updated_by: {初始化者}
updated_at: {ISO 时间戳}
reason: 新项目初始化，等参与者到齐
​```

## 规则
- `enabled: false` 或 `mode: stopped` → 立即停止，不处理不投递
- `mode: readonly` → 只读不写
- 改时必须填 updated_by / updated_at / reason 三项
```

| 字段 | 说明 |
|---|---|
| `enabled` | `true` / `false` |
| `mode` | `normal` / `readonly` / `stopped` |
| `updated_by` | 谁改的，**必填** |
| `updated_at` | **系统命令取的真实时间**，不许估 |
| `reason` | 为什么改 |

> ⚠️ 本文件里会出现 `enabled: false` 这样的**示例文字**。
> 如果你写 cron 脚本匹配它，务必锚定 `## 当前状态` 下的代码块——
> 早期有个脚本用宽松正则匹配说明文字，误判成"项目停了"直接退出。

---

## STATE.md —— 共享状态

**中断后恢复的第一入口。** 每人只改自己的区块。

```markdown
## 全局
- 当前阶段：{一句话说清到哪了}
- next_msg_id: {下一个可用编号}
- 参与者列表：{ai-a}, {ai-b}
- 下一步：{最要紧的一件事}

## ai-a 区块
- session_id: {会话标识}
- last_active: {时间戳}
- status: active
- current: {正在干什么}
- next: {接下来干什么}
- 已知问题：{踩过的坑}
```

**规则**：全局区块的写权见协议第十节；各自的区块自己改，不碰别人的。
这个文件**每轮醒来必读**，所以别写长。

---

## DECISIONS.md —— 决策记录

**按需读**，不像 STATE.md 每轮必读，所以可以长。

```markdown
### D1：{决策标题}
- 决定：{选了 A}
- 理由：{为什么选 A 不选 B}
- 状态：已落地 / 待验证 / 已废弃
```

| 记什么 | 为什么 |
|---|---|
| 决策 + 理由 | 只记结论，下次还会有人重新提议同一件事 |
| **被否决的方案**也要记 | 否则隔两周有人再提一遍，大家重新吵一遍 |
| 协议变更记录 | 何时改了什么、为什么、谁改的 |

---

## HEARTBEAT.md —— 心跳日志

```markdown
| 时间 | 参与者 | 事件 |
|---|---|---|
| 2026-10-20T09:15:00+08:00 | ai-a | 建立框架，创建目录结构 |
| 2026-10-20T09:31:00+08:00 | ai-a | 处理 0042-task，译稿已交 |
```

**只记事实，不做判断。** 只追加，不覆盖。

判断由读到的人**自己算**——`当前时间 - 表里最后一条时间戳`。

> ⚠️ 本文件是**共享追加文件**，任何人写一笔都会刷新它的 mtime。
> 所以它**不能**用来判断谁活着——判活只能读 `inbox-{自己}\.alive` 的 mtime。

---

## LEASES.md —— 租约表

**防两个 AI 干同一件事。** 长任务开工前必须先抢占。

```markdown
## 活跃租约

| task_id | 持有者 | 开始时间 | 到期时间 | 状态 | 宿主 |
|---|---|---|---|---|---|
| 0042 | ai-a | 09:15:00 | 11:15:00 | working | ai-a |
```

| 字段 | 说明 |
|---|---|
| `task_id` | 对应消息序号 |
| `持有者` | **必须写名字**，否则别人看到 claimed 不知道是不是自己的 |
| `到期时间` | 超过它没续期，**任何人可抢** |
| `状态` | `claimed` / `working` / `done` |
| `宿主` | 哪个 AI 在执行 |

**关键设计：带过期时间的租约，不是永久锁。** 持锁方崩溃会死锁，
比竞态后果更严重；租约会自己到期，最坏等一个周期。

- 续租：`working` 状态每 30 分钟刷一次时间戳
- 干完：改 `done`，**保留那一行**（便于追溯），不再视为占用
- 默认租约期 2 小时（轮询间隔 × 2）

---

## PROGRESS.md —— 长任务检查点

长任务写到这，崩了之后新会话靠它接着干。

```markdown
## 任务 0042：翻译三份文档

- 状态：第 2 份进行中
- 检查点：
  - [x] doc1.md 已译，术语一致
  - [ ] doc2.md 译到第 3 段（共 7 段）
  - [ ] doc3.md 未开始
- 下一步：从 doc2.md 第 4 段继续
- 坑：doc2 的表格跨页，译完要回来核对表头
```

**规则**：检查点要具体到"下一行从哪开始"，
只写"进行中"等于没写——新会话读了还是不知道该干什么。

---

## 一句话对照

| 文件 | 回答什么问题 | 谁读 |
|---|---|---|
| `SWITCH.md` | 现在能干活吗 | 每轮醒来第一个 |
| `STATE.md` | 现在到哪一步了 | 每轮必读，必须短 |
| `DECISIONS.md` | 为什么当初这么定 | 按需，可以长 |
| `HEARTBEAT.md` | 最近发生了什么 | 按需，只记事实 |
| `LEASES.md` | 这活有人干了吗 | 接长活前 |
| `PROGRESS.md` | 崩了从哪接着干 | 崩溃恢复时 |
