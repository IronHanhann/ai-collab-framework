# 身份、记忆与容量

> 每个参与者在这里登记**自己是谁**。换模型时，新执行器**先读这个文件**，
> 就知道自己是谁、上任干了什么。

## 1. 身份 ≠ 模型（最重要的一条）

```
身份 = 软件槽位（固定）          ← 长期稳定
模型 = 可替换的执行器            ← 随时可换
记忆 = 存在【文件】里，不存模型里 ← 跨模型继承
```

**关键推论**：记忆必须在文件里，不能在模型里——因为模型会被换掉，文件不会。

## 3. 给下一任的信

> 换模型/换执行器前，在这里留一段：现在到哪一步、待办是什么、有什么坑。
>
> **注意**：这是锦上添花。STATE.md 和 DECISIONS.md 才是承重墙——
> 上一任若没能留信（比如额度耗尽），新执行器靠这两个文件也要能接手。

## 4. 上下文容量

**不许在自动轮次里"全量读收件箱"。** 只读 STATE.md + **未处理**的消息。

| 层级 | 内容 | 谁读 | 何时读 |
|---|---|---|---|
| L0 摘要 | STATE.md 全局区 | 所有人 | 每轮必读 |
| L1 最近 | 最近几条未处理消息 | 对应收件人 | 处理时读 |
| L2 归档 | 已完结的往返 | 需要时 | 按需，不默认读 |
| L3 冷存档 | archive\ 目录 | 几乎不读 | 仅追溯 |

**收件箱是流水线，不是仓库。** 消息处理完就搬进 `archive\`。

## 5. 记忆三分

| 类型 | 存哪 | 说明 |
|---|---|---|
| 状态记忆 | STATE.md | 现在到哪一步了（每轮必读，必须短） |
| 决策记忆 | DECISIONS.md | 为什么选 A 不选 B，**理由要写** |
| 教训记忆 | LESSONS.md | 踩过的坑，别再犯 |

记决策必须带"为什么"——只记结论，下次还会有人重新提议同样的事。
