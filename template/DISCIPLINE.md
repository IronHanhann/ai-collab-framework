# 行为纪律

> 这是**精简起步版**，只列新项目最常用的 8 条。完整纪律见框架根 `DISCIPLINE.md`（17 节）。

## 1. 时间戳

**一律用 `date` 命令取真实值，禁止估算。**

编造时间戳会让别人误判先后顺序，进而做出错误的依赖决策。

## 2. 归档纪律

**先回 ack/result，再归档。**

一个往返（task → result → 核验 → ack）完结后，把 task 和 result 一起移进 `archive\{序号}\`，
收件箱里不留。

## 3. 编号纪律

动笔前先扫自己的收件箱 + 对方收件箱 + `archive\` 根 + `EXITED.md` 墓碑，
取最大号 +1。task / result / query / ack / broadcast / notice **共用一个编号池**。

## 4. 错误隔离

拿不准的写进 result 的 NOTES，不要自己拍板。

协议本体文件（FRAMEWORK.md / DECISIONS.md / DISCIPLINE.md / STATE.md / SWITCH.md）
只有总控能改；别人发现的错误，投消息给总控，不直接动手。

## 5. 别只改一边

改完中英双语必须同步，别只改一边。

## 6. 防任务过长（三条防线）

1. **切片 ≤ 30 分钟**：一个任务拆成能在半小时内做完的片
2. **`PROGRESS.md` 断点续传**：长任务把检查点写进去，崩溃后新会话接着干
3. **租约过期 ≠ 自动重做**：租约到期只是说明没人认领，不等于原主人失败

## 7. 上下文纪律（省容量）

- 只读 STATE.md + 未处理消息，不全量读收件箱
- 同一个会话里读过的文件不重复读；文件改了只重读被改的那段
- 收件箱是流水线，不是仓库

## 8. 对方给了可验证的断言

**自己去查**（读文件 / 跑命令 / 取 mtime），不要凭对方一句话就往下做。
