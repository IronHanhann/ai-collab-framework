## 🎯 这是什么

多个 AI 在你磁盘上通过一个文件夹互相通信。**不用 API。不用服务器。不用网络。不用中间件。不用写代码。** 一个共享目录就是全部基础设施。

它不是软件，是一套约定——所以它不会因为平台升级而坏，也不会因为模型换代而废。

---

## 💡 为什么选这个

市面上多智能体方案大多要你装个 SDK、注册个 API key，或者把数据交给别人的托管服务。这套只要一个文件夹。

| | 别的方案通常 | 这套框架 |
|---|---|---|
| 上手 | 装插件 / 注册 API key | 复制一个文件夹 |
| 谁能接入 | 只支持那家平台上的 AI | **任何能读写文件的 AI** |
| 升级会坏吗 | SDK 版本、平台 API 变更 | 不会——它是约定，不是依赖 |
| 运行成本 | 按调用计费 | 零（AI 的钱你本来就在付） |
| 数据在哪 | 别人的服务器 | 你的磁盘 |
| 你能看到每条消息吗 | 只能通过他们的工具 | **打开文件夹。全是纯 markdown。** |
| 能手动改"配置"吗 | 他们的设置界面 | **改一个文件。这就是全部配置。** |

这里不点名任何项目——不是说别人不好，而是这一类东西都有上面那个形状，而这个不是。

---

## ⚡ 它给你的七样东西

1. **一句话接入任何 AI**——能读写文件就能进来。DeepSeek、豆包、Claude、GPT、Kimi、你自己的 agent 都行。
2. **崩溃恢复就是读个文件**——没有会话要恢复，没有 token 要刷新。AI 死了、额度没了、换模型了？开个新的，它读 `STATE.md` 接着上次的地方干。
3. **AI 崩了也搞不坏别人的邮箱**——每次写入都是先写 `.tmp` 再改名，读方跳过 `.tmp`。写了一半的消息不存在。
4. **不会两个 AI 干同一件事**——干活前先用带时限的租约占上。租约会过期，所以持有人崩了也不会把谁卡死。
5. **你随时能看见一切**——每条消息都是文件夹里的纯 markdown，用任何编辑器都能打开。没有仪表盘、没有查询语言、没有日志接入。
6. **规则能手改**——翻开关、换总控、改轮询间隔，每件都是改一个文件。**你不是在操作软件，是在改配置。**
7. **你不再是传声筒**——转发这套事框架干了。你负责监督、拍板、改开关。

## 🏗 架构

```
AI-A 写文件 → 共享文件夹 → AI-B 读文件 → 写回复 → AI-A 读回复
```

每个 AI 有自己的收件箱。别人往里投文件，它定时醒来（或者你戳一下）读新消息、处理、写回。**AI 的邮箱——只不过邮箱是磁盘上的一个文件夹，投递免费。**

**为什么用文件？** 不是每个 AI 平台都给你开 API，但几乎所有 AI 都能读写文件。

### 三种角色

| 角色 | 干什么 | 类比 |
|---|---|---|
| **总控** | 全局协调、管协议、分配号段 | 包工头 |
| **业务 AI** | 干具体的活（代码、翻译、文档、review） | 工人 |
| **你** | 监督、拍板、改开关 | 甲方 |

**总控是一个职位，不是一个身份。** 你指定一个 AI 当总控，它读 `CONTROLLER.md` 就知道自己该干什么。想换？改这个文件，一行的事。总控死了不会出大事——工人们照常干，你重新指定一个包工头就行。

## 🚀 快速开始（一句话接入）

> **每个会话的第一条规矩**：动手之前先读 `projects/{项目名}/ROLE.md`——它写明你属于哪个项目、哪个收件箱是你的、什么不许碰。没有 `ROLE.md` 就改读 `SWITCH.md`。**不许跨项目读文件**（FRAMEWORK.md 18.3 规则 5）

### 1. 建一个项目

```powershell
# 复制模板
xcopy /E /I "template" "projects\我的项目"

# 每个 AI 一个收件箱
mkdir "projects\我的项目\inbox-ai-a"
mkdir "projects\我的项目\inbox-ai-b"
```

### 2. 给 AI 发接入指令

把下面这段话发给任何一个 AI——复制直接用：

```
你现在接入 AI Collab Framework。
先读 SKILL.md，按协议跟我协作。
你的收件箱是 projects\我的项目\inbox-ai-a\
按定时器醒来（默认 15 分钟，可按需调整），流程见 SKILL.md。
```

这就是全部安装步骤。**不用插件、不用调 API、不用写代码。**

### 3. 启动

编辑 `projects\我的项目\SWITCH.md`，把 `enabled` 改成 `true`。

> 新项目的开关**默认是关的，故意的**——人还没到齐就打开，只会空转烧额度。

## ⚠️ 需要人来监管

这套框架靠的是 AI **自觉遵守**规则，不是强制校验。规则是 AI 自愿遵守的约定，没有任何硬检查能拦住 AI 违规。

- **AI 是单线程、注意力有限**，容易漏：改了一处忘了同步另一处，检查清单漏项。
- **别完全放养。** 定期自己去看 `cron-log.md`、`STATE.md` 和检查结果，别指望 AI 能自己发现所有问题。
- **`check.ps1` 只做机械一致性检查。** 它只能查“能自动查的”（文件缺失、`.alive` 过期、三处副本漂移）；语义和逻辑错误仍然要人来看。

> AI 不会自己监督自己，你的定期一眼，才是兜底。

## 🔄 消息怎么流转

每轮醒来（定时器，或者你戳它一下）：

```
1. 读总开关   →  disabled？全停，别重建定时器。
2. 读项目开关 →  disabled？跳过这个项目，定时器保留。
2.5 读 ROLE.md → 你是哪个角色槽位？只干自己的活
3. touch .alive → 写你自己的时间戳，别写别人的
3.5 回读 .alive mtime → 不一致？写入失败，下轮重试
4. 扫已用编号 → 你的收件箱 + archive + 墓碑
5. 读 STATE.md + 收件箱新消息
6. 处理消息 → 先占租约，再写回复
7. 追加 cron-log.md 一行
```

每条消息就是一个文件，命名 `{序号}-{发送者}-{类型}.md`，头部是统一的 `META`。一次完整往返（task → result → ack）见 [examples/messages.md](examples/messages.md)。

## 🧑‍💻 最容易被忽略的一条：同一个 AI 开多个会话

你不需要不同厂商。一个豆包会话当开发、另一个当 reviewer；一个 DeepSeek 做调研、一个写代码。它们不会撞号——各自是各自的收件箱、各自的 `.alive`、各自的身份。

这是多数框架没有的能力，也是"你手上只有一个好用的 AI、但想听它第二意见"时唯一能用的办法。

**为什么不会串**：身份认的是收件箱目录，不是模型名。同一个模型的两个会话就是两个文件夹。槽位名是会话级的——同一个软件在不同项目里必须用 `{软件名}-{项目名}`，这样会话永远读不到别的项目的信。

## 🔧 内置了什么

| 机制 | 干什么用 |
|---|---|
| 📦 **零依赖** | AI 能读写文件就能接。不用 SDK、不用 API key、不用装东西。 |
| 🌐 **跨平台** | DeepSeek、豆包、Claude、GPT、Kimi、任何自定义 AI——都能接。 |
| 💥 **崩溃恢复** | 状态全在磁盘上。AI 死了、额度没了、会话重置了？开个新的，读文件从断点接着干。 |
| 🔄 **多项目** | 同时跑好几个独立协作项目，互相完全隔离。 |
| 👑 **总控角色** | 一个 AI 全局协调。总控失联 → 业务照跑，不自动接管（免得俩候选打架）。 |
| 🔢 **消息编号** | 每条消息从一个共享池里取号。不丢、不重。 |
| 📝 **ACK 确认** | 收到消息回个 ack，发送方就知道你真看到了。 |
| 🔒 **租约机制** | 干活前先"占位"。不会两个 AI 抢同一个活。租约会过期——不会死锁。 |
| 🔘 **双层开关** | 总开关全停，项目开关停单个。改一个文件 = 完全控制。 |
| 💚 **`.alive` 心跳** | 每个参与者私有存活文件，只有本人能写。所以共享的心跳日志证明不了谁还活着。 |
| 🪦 **退出墓碑** | AI 要走就写 `EXITED.md`，把没干完的事交代清楚。不玩消失。 |
| ⚛️ **原子写入** | 先写 `.tmp` 再改名。永远没人读到写了一半的消息。 |
| 🧑‍💻 **同模型多会话** | 同一个 AI 开多个会话当不同角色。它们不会撞号。 |

## 🖥 日常操作

| 你想干啥 | 你干啥 |
|---|---|
| 全部停掉 | 改根目录 `SWITCH.md`，`enabled: false` |
| 只停一个项目 | 改 `projects/{项目名}/SWITCH.md`，`enabled: false` |
| 看谁在干活 | 读 `projects/{项目名}/STATE.md` |
| 看 AI 活着没 | 读 `projects/{项目名}/inbox-{AI}/.alive` 的 mtime——30 分钟没动就是失联。**不要**看 `HEARTBEAT.md` 的 mtime：它是共享文件，任何人写一笔都会把它刷新 |
| 开新项目 | 复制 `template/` → `projects/{新项目名}/`，然后接 AI |
| 给项目加新 AI | 在 `PARTICIPANTS.md` + `IDENTITY.md` 注册、建 `inbox-{新AI}/`、在 `STATE.md` 加区块、在 `HEARTBEAT.md` 记一行、再广播。让在场的 AI 去办，它手里有清单 |
| 换总控 | 改 `CONTROLLER.md`，一行 |
| 总控失联了 | 它 `.alive` 冻结、也不会接管你的项目。业务项目照跑，紧急 bug 自己修完广播。新总控由**你**指定，不会自动晋级 |
| 两个 AI 在干同一件事 | 查 `projects/{项目名}/LEASES.md`——一个任务一个主人一条租约 |
| 崩溃后怎么接着干长任务 | 读 `projects/{项目名}/PROGRESS.md`，检查点在里面 |
| 动手前先知道谁是谁 | 读 `projects/{名字}/ROLE.md`——角色槽位、你管什么、什么不许碰 |
| 已发出的消息不许偷偷改 | 发出去就是发出去了，写错发更正消息（新编号），不改原文 |

**所有操作本质都是改文件。** 你不是在操作软件，是在改配置。

## 🧪 原理和限制

**原理。** 状态全在磁盘上，所以任何东西都不靠对话上下文存着。AI 死了，下一个读文件就能接上；模型换了，新执行器读 `IDENTITY.md` 就知道自己是谁；任务长，检查点在 `PROGRESS.md` 里，崩了只丢几分钟不丢整锅。

**它做不到的。** 不是实时的——参与者靠轮询，或者你戳它。所有人都要能访问同一个目录。消息编号是项目内的，跨项目防撞靠槽位命名而不是全局登记。文件是明文，别放敏感信息；要隐私就把文件夹放加密磁盘上。

它是约定的遵守者，不是沙箱——理论上 AI 可以不守规矩。所以协议要求时间戳必须用系统命令取、不许用模型自己报，也所以任何说法都该拿磁盘核验。

## 📖 它是真跑过的

这不是纸上设计。协议是**一边被两个 AI 用着协作、一边定出来**的，里面每条规则背后都有事：

- **58 条编号消息、119 份归档文件**，一天的活
- **3 个参与者里 2 个在不同平台**——其中一个中途**换了三次执行器**（两次是额度耗尽）。对面完全没感觉到；身份认的是文件夹，不是模型。
- **撞过两次号**，然后改了编号规则把洞堵上——那条规则是因为事故才有的，不是凭空写的
- **有一个参与者中途退出**，退出流程跑了个全套：墓碑、未竟事项交接、广播给所有人
- **活性检测静默失效了 76 分钟**——心跳文件不刷新，因为脚本匹配到了文档说明里的示例文字。查出来、修了，并且因此给协议加了"写完必须回读验证"这一步
- `.alive` 这套机制本身就是采纳**对方**的建议——因为先证明了共享心跳日志不可靠

上面的数字是从框架自己的运行记录里数出来的，不是估算。

    ├── HEARTBEAT.md      # 心跳日志（只记事实）
    ├── LOG.md            # 消息记录
    ├── LEASES.md         # 租约表（防止重复干活）

    ├── check.ps1         # 一致性检查脚本
    ├── CRON-TEMPLATE.md  # 定时器 prompt 模板
    ├── inbox-controller/ # 总控收件箱（问题都投这）

你的实际项目放在 `projects/` 里（git 不跟踪，所以你的数据不会进仓库）。每个项目都是 `template/` 的一份拷贝，外加一个 `cron-log.md`。

按协议，**框架根只有一个开关**——`SWITCH.md` 总开关；指定了总控才有 `CONTROLLER.md`；再加上协议本体 `FRAMEWORK.md` 和操作手册 `USER-GUIDE.md`。其他全在项目里面，这样第二个项目永远动不到第一个项目的状态。

```
{协作根目录}\
├── SWITCH.md              # 总开关——每轮醒来第一个读它
├── projects\
│   ├── my-project\        # template/ 的一份拷贝 + cron-log.md
│   └── my-other-project\
├── FRAMEWORK.md           # 协议本体
├── USER-GUIDE.md          # 给人看的操作手册
└── template\              # 空白项目模板——新建项目就复制它
```

**所有项目级文件都在 `projects/{项目}/` 下**——`SWITCH.md`、`STATE.md`、`DECISIONS.md`、`HEARTBEAT.md`、`LEASES.md`、`PROGRESS.md`、`DISCIPLINE.md`、`IDENTITY.md`、`PARTICIPANTS.md`、`cron-log.md`、`LOG.md`、`CONTROLLER.md`、`inbox-*`、`archive/` 都在里面。完整目录见 [examples/structure-two-ai.md](examples/structure-two-ai.md)，那六个状态文件各自填什么见 [examples/root-files.md](examples/root-files.md)。

## 🧪 使用场景示例

- **代码 review**：AI-A 写代码，AI-B 在收件箱里写 review 意见，AI-A 读了改。
- **翻译项目**：AI-A 翻译，AI-B 校对，AI-A 修改。全程靠文件。
- **换模型不丢上下文**：DeepSeek 额度没了？开豆包，它读状态文件接着干。
- **同模型多会话**：一个豆包会话当"开发"，另一个当"reviewer"。它们通过文件协作，互不干扰。
- **互相查作业**：发个 `task` 让另一个 AI 审你的协议。它能看出你看不见的问题。

1. 改 `SKILL.md`（协议本体）
2. 如果改了结构，同步改 `template/`
3. 更新 `SKILL.md` / `README.md` / `README.zh-CN.md` 里的版本号
4. 总控 AI 负责同步线上部署和这个开源包

> **三处同批改**：改协议必须同时落到框架根目录、每个线上项目、以及 `template/`。让它们漂移的后果是项目在遵守一套已经没人认的规则。
